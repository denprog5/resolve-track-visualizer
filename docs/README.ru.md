# Resolve Track Visualizer

[English README](../README.md)

Resolve Track Visualizer создаёт музыкальные плееры поверх аудиоклипов таймлайна DaVinci Resolve. Lua-скрипт читает активный таймлайн, встроенный engine готовит обложки, теги, волну и статичные слои плеера, а каждый плеер — лёгкая Fusion-композиция, где время и прогресс считаются выражениями.

## Возможности

- Пять скинов: `Классический`, `Минимал`, `Вертикальное стекло`, `Компактный` и `Волна`, у каждого свои настройки и палитра по умолчанию.
- Четырнадцать встроенных палитр и собственные сохранённые палитры, которые подходят к любому скину.
- Пресеты плееров: полный стиль (скин, расположение, элементы, цвета, шрифты) сохраняется под именем, применяется позже, переименовывается, удаляется, экспортируется и импортируется файлом `.tviz-preset.json`.
- Учёт DJ-миксов: треки, разложенные по нескольким аудиодорожкам и перекрывающиеся кроссфейдами, дают один непрерывный ряд плееров. Точка переключения выбирается: середина кроссфейда, старт следующего трека или конец текущего. Клип, целиком звучащий внутри другого трека, отдельного плеера не получает.
- Подрезка с любой стороны учитывается: время и прогресс начинаются с реального смещения в исходном файле; прогресс может показывать позицию во всём треке или в клипе.
- Неблокирующая панель: вид плеера, таймлайн и крупное превью на одной странице; тонкая настройка на вкладке `Вид`, пресеты и палитры в `Библиотеке`, журнал, язык и обновления в `Сервисе`.
- Длинное название трека, которое не помещается в строку, прокручивается целиком, чтобы его можно было прочитать (отключается в настройках скина).
- Подписанные автоматические обновления: установленный плагин сам обновляется из GitHub Releases.

## Статус

Версия `0.9.0` — preview-версия на пути к 1.0. Она проверена только с **DaVinci Resolve Studio 20.2.1 на Windows x64**. Текущий интерфейс UIManager требует Resolve Studio, поэтому Resolve Free не поддерживается. Проверка Resolve 21 отложена; Resolve 19 и старше, Resolve 21 и Resolve на Linux не сертифицированы. См. [матрицу совместимости](compatibility.md).

Публикуется только Windows x64. Linux x64 собирается только отдельным ручным canary workflow и никогда не публикуется. macOS не поддерживается, не собирается и не входит в текущий release scope. Наличие build target не означает, что работа плагина проверена внутри Resolve. Точные ограничения описаны в [release process](releasing.md).

Релизы публикуются на [странице Releases](https://github.com/denprog5/resolve-track-visualizer/releases). Исполняемые файлы для Windows **пока не подписаны Authenticode** (запрошена бесплатная подпись для open-source проектов через SignPath Foundation, см. [политику подписи кода](code-signing-policy.md)), поэтому при первом запуске Windows SmartScreen может показать «Система Windows защитила ваш компьютер»: нажмите **Подробнее → Выполнить в любом случае**. Автообновления от Authenticode не зависят: они проверяются собственной подписью Ed25519 проекта.

Артефакты workflow хранятся один день; публикует что-либо только запущенный мейнтейнером release-запуск. Перед тем как сделать репозиторий публичным, нужно удалить все сохранённые native-артефакты и соответствующие workflow runs: завершённый workflow не может защитить уже сохранённые данные. К каждому релизу приложен `SHA256SUMS`, а собранный артефакт распаковывается в `artifacts/`, `source/` и корневой `SHA256SUMS`. Перед запуском из корня распакованного артефакта нужно проверить все относительные пути:

```bash
sha256sum -c SHA256SUMS
```

## Язык

При первом запуске режим `Авто (системный)` выбирает русский для русскоязычной системы и английский для всех остальных языков. Настройки пользователей предыдущей русскоязычной версии при миграции остаются на русском.

Язык можно изменить на вкладке `Сервис`, поле `Язык`. После изменения закройте и снова откройте Track Visualizer; настройки тем и стилей сохранятся. Установщик также принимает `--language auto`, `--language en` и `--language ru`.

## Установка

Пользователю не нужны отдельно установленные Python или FFmpeg. Скачайте `TrackVisualizerSetup-<версия>-windows-x64.exe` из последнего релиза и запустите его.

Installer размещает engine и FFmpeg в:

```text
%LOCALAPPDATA%\DavinciTrackVisualizer\
```

Resolve-скрипт устанавливается в:

```text
%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Scripts\Utility\Track Visualizer.lua
```

После установки полностью перезапустите Resolve и откройте:

```text
Workspace -> Scripts -> Utility -> Track Visualizer
```

В русском интерфейсе пункт находится в `Рабочая область -> Сценарии -> Utility -> Track Visualizer`.

Если пункт меню не появился, проверьте путь к Lua-файлу и убедитесь, что Resolve был полностью закрыт перед повторным запуском.

Удаление выполняется тем же setup-файлом:

```powershell
.\TrackVisualizerSetup-0.9.0-windows-x64.exe --uninstall --no-pause
```

Удаляются только управляемые runtime-файлы и Resolve-скрипт. Настройки, логи, задания, временные и отрендеренные файлы сохраняются.

Отдельный ручной workflow готовит unpublished Linux x64 canary, требующий glibc 2.28 или новее. Packaging smoke проходит на Windows и Linux, но интеграция с Resolve проверена только на Windows x64.

## Обновления

Установщик нужно запустить только один раз. Дальше Track Visualizer обновляется сам:

- при открытии панели (не чаще раза в шесть часов) он в фоне проверяет последний GitHub Release, скачивает новый установщик и проверяет подпись релиза, размер и SHA-256;
- когда плееры не создаются, обновление ставится тихо, настройки, пресеты и палитры сохраняются. Закройте и снова откройте панель, чтобы перейти на новую версию;
- в `Сервис → Обновления` видна установленная версия, есть кнопка `Проверить обновления` и переключатель автообновления.

Версии старше 0.9.0 обновляться сами не умеют: установщик 0.9.0 нужно один раз запустить вручную.

## Работа В Resolve

1. Разместите музыкальные клипы на дорожках `A1`, `A2`, `A3`; кроссфейды и подрезка допустимы.
2. Откройте Track Visualizer. На вкладке `Плееры` выберите скин, палитру или сохранённый пресет — превью обновится сразу.
3. Укажите аудиодорожки (например `1-3`), видеодорожку для плееров (по умолчанию `V2`) и режим наложения треков.
4. Нажмите `Создать плееры`. Повторный запуск заменяет плееры на этой видеодорожке, `Удалить плееры` убирает их.

Поле `Клипы` позволяет обновить только часть плееров: номера, диапазоны (`3,5-7`) или `@playhead`; `Список клипов` выводит номера в журнал.

Плееры ставятся только на свободный участок выбранной видеодорожки. Служебный carrier-клип и слои хранятся в корзине Media Pool `Track Visualizer`; helper timelines больше не создаются. Кнопка `Удалить старые служебные таймлайны` на вкладке `Сервис` убирает таймлайны `TVIZ__SOURCE__`, оставшиеся от прежних preview-версий.

## Метаданные И Файлы

Поддерживаемые входные форматы: MP3, WAV, FLAC, M4A, AAC и OGG. Название, артист, альбом и embedded cover читаются через Mutagen. При отсутствии обложки используется bundled `aplus.png` или выбранная пользователем PNG.

Пути и теги обрабатываются как UTF-8. Если Resolve не возвращает путь к исходному аудио через официальный API, диагностические свойства первого такого клипа записываются в:

```text
%LOCALAPPDATA%\DavinciTrackVisualizer\tmp\clip_property_dump.txt
```

Настройки пользователя сохраняются в:

```text
%LOCALAPPDATA%\DavinciTrackVisualizer\settings.json
```

Пресеты и палитры хранятся в `settings.json`; экспортированные пресеты по умолчанию лежат в `%LOCALAPPDATA%\DavinciTrackVisualizer\presets`.

После изменения подрезки, позиции или тегов клипов снова нажмите `Создать плееры`.

## Разработка

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m unittest discover -s tests -v
```

Каталог скинов внутри Lua-скрипта генерируется из `davinci_track_visualizer/skins.py`: после изменения скинов или палитр запустите `python scripts/sync_lua_catalog.py` (проверка: `--check`).

Установка dev-версии в текущий Resolve:

```powershell
.\.venv\Scripts\python scripts\install_resolve_script.py
```

Поддерживаемый воспроизводимый путь release-сборки — запускаемый вручную GitHub Actions workflow, см. [release process](releasing.md). Прямой запуск `scripts/build_release.py` является расширенным эквивалентом: он требует строго Python 3.12.10 на Windows или 3.12.13 на Linux, проверенную парную сборку FFmpeg/FFprobe и явные значения `--ffmpeg-license`, `--ffmpeg-version`, `--ffmpeg-source-url` и `--ffmpeg-source-sha256`. Одного наличия FFmpeg в `PATH` недостаточно. На Windows также нужно передать проверенные файлы через `--windows-libffi-license` и `--windows-openssl-license`; скрипт дополнительно проверяет изоляцию Python user site.
